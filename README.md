# خيرات Foods — إدارة الأعمال

خيرات Foods تطبيق عربي RTL لإدارة العملاء والأصناف والفواتير والمصاريف والمخزون والتقارير، مصمم أولًا لشاشات الهاتف ويعمل من خلال جلسة خادمية مرتبطة بـ MongoDB. تحتفظ الواجهة بنسخة تشغيلية محلية في IndexedDB، بينما تبقى MongoDB مصدر الحقيقة عند الاتصال.

## التشغيل المحلي

```bash
pnpm install
pnpm dev
```

للفحص قبل التسليم:

```bash
pnpm check
pnpm test
pnpm build
```

يتطلب التشغيل المتصل متغير `MONGODB_URI`، إضافة إلى `JWT_SECRET`. لا تضع بيانات الاعتماد داخل المستودع؛ استخدم إدارة Secrets في بيئة المشروع أو ملف `.env` محلي غير متعقب. لا يوجد ملف `.env.example` ضمن هذا القالب المُدار لأن أسماء وقيم الأسرار تُدار من إعدادات المشروع، ويجب إدخالها عبر بطاقة Secrets بدل حفظها في الملفات.

## الوظائف المتاحة

تتضمن الواجهة تسجيل دخول إلزاميًا، أدوار `ADMIN` و`USER`، لوحة مؤشرات، CRUD للعملاء والأصناف والمصاريف والمستخدمين، فواتير متعددة الأصناف مع البحث وتعبئة السعر والخصم والمدفوع والمتبقي، خصم المخزون، اسم الحساب المنشئ، إلغاء الفاتورة بدل حذف السجل المالي، كشف حساب العميل مع الفواتير والمدفوعات، فلاتر زمنية، وتصدير CSV من التقارير والفواتير.

تظهر التكلفة والربح للمشرف فقط. ويعيد الخادم بيانات منقاة للمستخدم العادي، ولا ينبغي اعتبار أي حالة محلية أو متغير واجهة بديلًا عن التحقق الخادمي.

## الحسابات التشغيلية الأولية

| الدور | اسم المستخدم | كلمة المرور |
|---|---|---|
| مدير النظام | `admin` | `Admin123!` |
| موظف المبيعات | `sales` | `Sales123!` |

غيّر كلمات المرور بعد أول دخول. لا تستخدم الحسابات الأولية في بيئة العميل دون تغييرها.

## العمل دون اتصال والمزامنة

عند انقطاع الاتصال، تُحفظ عمليات الإضافة المحلية في IndexedDB داخل `syncQueue` مع `clientOperationId`. عند عودة الاتصال أو كل 30 ثانية يحاول التطبيق رفع العمليات إلى `/api/sync` باستخدام `Idempotency-Key`. توجد إعادة محاولة تصاعدية حتى خمس محاولات، ويحفظ الخادم مفاتيح العمليات المعالجة في مجموعة MongoDB `syncoperations` لمنع التكرار بعد إعادة التشغيل.

تبقى العمليات الفاشلة ظاهرة في مؤشر المزامنة ولا تُحذف تلقائيًا. يجب مراجعة العمليات الفاشلة قبل الاعتماد على البيانات في نهاية يوم العمل، لأن فض تعارضات التعديل المتزامن ما زال إجراءً يدويًا في هذه النسخة.

## PWA والبيانات المحلية

يرتبط التطبيق بملف `manifest.webmanifest` وservice worker ويمكن تثبيته من متصفح الهاتف عبر HTTPS. يخزن service worker ملفات الواجهة فقط؛ أما بيانات الأعمال فتوجد في IndexedDB وMongoDB ولا ينبغي اعتبار Cache نسخة احتياطية.

## النسخ الاحتياطي والاستعادة

النسخ الاحتياطي الحقيقي يتم من MongoDB Atlas أو أداة MongoDB المناسبة، وليس من Cache المتصفح. قبل تسليم نسخة للعميل، فعّل النسخ الاحتياطي الدوري في Atlas أو صدّر قاعدة البيانات إلى مخزن آمن مشفر، واختبر الاستعادة على قاعدة منفصلة. احتفظ بنسخة من المشروع ونسخة إعدادات Secrets منفصلة عن المستودع.

## البيانات الحالية

تم تنظيف بيانات الاختبار السابقة وإدخال بيانات تشغيلية عربية مترابطة: مستخدمان، ثلاثة عملاء، أربعة أصناف، فاتورتان، دفعة واحدة، وثلاثة مصاريف. لا تستخدم البيانات الحالية كبديل عن نسخ العميل الاحتياطية.

## ملاحظات معروفة قبل الإنتاج

تعديل الفاتورة الخادمي يدعم جميع السطور في الفاتورة متعددة الأصناف، ويعيد تسوية المخزون ورصيد العميل ويسجل حركة `INVOICE_EDIT`. يتم تمثيل الإرجاع التشغيلي عبر إلغاء الفاتورة: يعيد الكمية إلى المخزون، ينشئ حركة `RETURN`، ويخفض رصيد العميل دون حذف السجل المالي. كما أن فض التعارضات بين تعديلات offline المتزامنة غير آلي، ويجب اختبار تدفقات التعديل والإلغاء والحذف المنطقي على بيانات منفصلة قبل تشغيل إنتاجي واسع.

## التدقيق والاختبارات

يحتوي `QA_HANDOFF.md` على نتائج الجولات الموثقة. وتشمل الاختبارات الآلية الحالية المعادلات المالية، تنقية بيانات التكلفة حسب الدور، قواعد الفاتورة متعددة الأصناف، المصادقة، واتصال MongoDB. شغّل `pnpm test` و`pnpm check` و`pnpm build` قبل إنشاء checkpoint جديد.
